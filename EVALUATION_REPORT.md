# Evaluation Report: HR Policy Q&A Fine-Tuning

## 1. Executive Summary

This report documents the evaluation of a two-stage fine-tuning pipeline (LoRA SFT followed by DPO) applied to Mistral 7B Instruct v0.2 for HR policy question answering. The system was trained on preference data generated by a RAG pipeline (GPT-4o + ChromaDB) over 533 HR policy documents and employee handbooks.

**Key results:**
- **SFT** raised ROUGE-L **1.78x** (0.164 → 0.293), producing concise, policy-grounded responses
- **DPO** improved preference quality — preferred by a GPT-4o-mini judge over SFT in **62.6%** and over Base in **57.6%** of comparisons
- The full RLHF pipeline (SFT + DPO) works end-to-end within Kaggle's free GPU tier

> **Read the numbers with Section 9 in hand.** The evaluation set is *not* prompt-disjoint from training — all 55 questions appear in both splits. The ROUGE-L figures therefore reflect a substantial degree of memorization and should not be read as generalization to unseen HR questions. The primary defensible claim in this report is that the **pipeline works end-to-end**, not that it achieves a particular benchmark score.

## 2. Experimental Setup

### 2.1 Models Evaluated

| Model | Description |
|-------|-------------|
| **Base** | Mistral 7B Instruct v0.2, 4-bit NF4 quantized, no fine-tuning |
| **SFT** | Base + QLoRA SFT adapter (r=16, alpha=32), trained 3 epochs on 648 preference pairs |
| **DPO** | Merged SFT + fresh DPO LoRA adapter (beta=0.3), trained 1 epoch on same preference data |

### 2.2 Test Set

- **198 test records** drawn from **55 unique HR questions**, spanning performance reviews, harassment complaints, sick leave, data privacy, resignation, overtime, remote work, parental leave, and more

> **Important — the test set is not prompt-disjoint.** The 90/10 split was applied at the *preference-pair* level, not the *prompt* level. All 55 questions appear in both the training and test splits, so every evaluated prompt was seen during training. This materially affects how the metrics below should be read — see [Section 9: Limitations](#9-limitations).

## 4. LLM-as-Judge Evaluation

### 4.1 Setup

- **Judge model:** GPT-4o-mini
- **Method:** Pairwise comparison — for each prompt, the judge receives both responses and picks a winner based on helpfulness, accuracy, relevance, and conciseness
- **Comparisons:** 3 pairwise matchups × 198 prompts = 594 total judgments
- **Errors:** 0 (all judgments valid)

### 4.2 Results

| Comparison | Model A Wins | Model B Wins | Winner |
|------------|-------------|-------------|--------|
| Base vs SFT | Base: 144 (72.7%) | SFT: 54 (27.3%) | **Base** |
| SFT vs DPO | SFT: 74 (37.4%) | DPO: 124 (62.6%) | **DPO** |
| Base vs DPO | Base: 84 (42.4%) | DPO: 114 (57.6%) | **DPO** |

**Statistical significance.** Win rates on n=198 carry roughly a ±7pp interval, so the raw percentages overstate how settled these results are. 95% Wilson score intervals and exact two-sided binomial tests against chance:

| Comparison | Winner's rate | 95% CI | p (vs 50%) | Verdict |
|------------|--------------|--------|-----------|---------|
| Base vs SFT | Base 72.7% | [66.1, 78.5] | 1.2e-10 | Decisive |
| SFT vs DPO | DPO 62.6% | [55.7, 69.1] | 0.00047 | Solid |
| Base vs DPO | DPO 57.6% | [50.6, 64.3] | 0.039 | **Marginal** |

All three clear the α=0.05 bar, but they are not equally strong. The Base vs DPO interval extends down to 50.6% — 0.6pp above chance — so that comparison should be treated as suggestive rather than established. The verbosity-bias result (Base vs SFT) is by far the most robust finding in this report.

Reproduce with `python -m src.eval.compare --recompute` (arithmetic only, no API calls).

### 4.3 Analysis: Two Metrics, Two Stories

The ROUGE-L and LLM judge metrics tell complementary stories:

**ROUGE-L says SFT is best** — it learned to produce concise, policy-specific answers that closely match the reference text. This is a measure of factual alignment.

**The judge says DPO is best** — it prefers DPO's more detailed, well-structured answers over SFT's shorter ones. This is a measure of perceived quality.

**Why does the judge prefer Base over SFT?** Verbosity bias. The judge lacks access to actual HR policy documents and cannot verify factual accuracy. Base writes 202 words of confident-sounding generic advice (citing FLSA, ADA, general best practices). SFT writes 131 words of correct but concise policy-specific answers. Without ground truth, the judge rewards thoroughness.

**Why does the judge prefer DPO?** DPO learned the balance — it writes more substantive answers than SFT (178 vs 131 words) while being more focused than Base (178 vs 202 words). It also has better structure and no hallucination instances.

**Key insight:** DPO optimized for what humans (or an LLM proxy) prefer, not for text overlap. This is exactly its design intent.

### 4.4 Illustrative Example

**Prompt:** "What is the company match percentage for the retirement plan?"

| Model | ROUGE-L | Response Summary |
|-------|---------|-----------------|
| Base (0.146) | Generic | "I'll need to clarify... this percentage can vary greatly from one company to another..." |
| SFT (0.231) | Concise | "I'd need to refer to the specific HR policy documents... Please let me know if you have access" |
| DPO (0.411) | Best | "Without specific context, I cannot provide an answer. Please refer to your organization's HR policy documents or contact the HR department directly" |

DPO gives the most appropriate response — acknowledging the limitation while directing to the right resource.

## 5. Qualitative Analysis

### 5.1 What SFT Learned Well

- **Policy-specific details:** Correctly references compensatory off rules, remote work policies, company-specific processes
- **Appropriate hedging:** When information isn't in training data, redirects to HR/policy documents
- **Concise formatting:** Learned bullet points and structured answers matching reference style
- **Highest ROUGE-L:** Closest to the ground-truth policy answers

### 5.2 What DPO Added

- **Better structure:** More organized, numbered responses with clear formatting
- **Preference alignment:** Produces responses that external evaluators prefer
- **Zero hallucination instances:** No cases of verbose off-topic responses
- **Balanced verbosity:** More detailed than SFT without Base's generic padding

### 5.3 Base Model Behavior

- Provides **generic, textbook-style** answers citing US federal law (FLSA, ADA)
- Uses **hedging language** ("I'd be happy to help, but...")
- Generates **longest responses** (202 words avg) with general best practices
- Never references any specific company policy or internal process

## 9. Limitations

These constraints materially affect how the results above should be interpreted. They are stated here rather than buried because several of them bound what this evaluation can legitimately claim.

### 9.1 The test set is not prompt-disjoint

The 90/10 split was applied at the preference-pair level rather than the prompt level. The consequence:

| | Unique prompts |
|---|---|
| Training split | 55 |
| Test split | 55 |
| **Overlap** | **55 (100%)** |
| Prompts never seen in training | **0** |

Every evaluated question was seen during training. This contradicts the held-out requirement stated in `project_brief.md`, and it affects the two metric families differently:

- **ROUGE-L is the most affected.** It measures n-gram overlap against reference answers the model was explicitly trained to reproduce for these same questions. The 0.164 → 0.293 improvement therefore reflects a substantial degree of memorization and cannot be read as generalization to unseen HR questions.
- **The judge win rates are partially insulated.** SFT vs DPO is a fair comparison in that both models trained on identical data, so neither holds a memorization advantage over the other. Base vs SFT/DPO is less clean, since only the latter saw the questions. All comparisons remain on seen prompts.

Correcting this requires re-splitting by prompt (holding out ~11 of the 55 questions) and retraining — not merely re-scoring the existing generations, which came from models trained on everything.

### 9.2 Small and narrow corpus

The preference dataset derives from only **55 unique questions** (9 candidate responses each). `project_brief.md` targeted 5,000–10,000 pairs; the realized dataset is roughly an order of magnitude below that. With 55 questions, both the DPO training signal and the evaluation are underpowered, and per-metric differences of a few points are within noise.

### 9.3 Reference answers are refusal-heavy

A large share of the `chosen` reference answers decline to answer — "the provided context does not contain…", "please refer to your HR department":

| Split | Refusal-style references |
|---|---|
| Train | 742 / 1780 (42%) |
| Test | 91 / 198 (46%) |

So a meaningful portion of what SFT learned is *appropriate declining* rather than substantive policy knowledge. This is defensible behavior for a grounded RAG-distilled model — declining beats hallucinating — but it means "domain adaptation" overstates what was learned. The retirement-plan example in Section 4.4 is precisely this case: all three models decline, and DPO scores highest for declining most cleanly.

### 9.4 The judge has no ground truth

As analyzed in Section 4.3, GPT-4o-mini judges without access to the source policy documents and cannot verify factual accuracy, which is why it rewards Base's confident generic prose over SFT's shorter grounded answers. Win rates here measure perceived quality, not correctness.

### 9.5 Training runs were not logged

W&B was disabled during both Kaggle runs (`WANDB_DISABLED=true`), so no loss curves or KL-divergence traces were retained. The DPO beta value of 0.3 is documented in code comments as chosen after 0.1 diverged and 0.5 proved too conservative, but no run artifacts survive to evidence that comparison.

## 10. Conclusion

The defensible claim from this work is that **the full RLHF pipeline runs end-to-end on free-tier compute** — RAG-based preference generation, QLoRA SFT, DPO alignment, and a dual-metric evaluation harness, in ~2.5 GPU-hours on a single Tesla P100.

1. **SFT** measurably shifted the model toward the reference style — shorter responses (131 vs 202 words), higher lexical diversity, and higher ROUGE-L. On seen prompts, so partly memorization (Section 9.1).

2. **DPO** produced responses an LLM judge preferred over both SFT (62.6%) and Base (57.6%), with no verbose off-topic outputs. Since SFT and DPO trained on identical data, this comparison is the least contaminated result in the report.

3. **The two metrics disagreeing is the most interesting finding** — ROUGE-L favors SFT, the judge favors DPO — and the verbosity-bias explanation in Section 4.3 holds independently of the split problem.

4. **What this evaluation cannot show** is generalization to unseen HR questions. That requires the prompt-level re-split described in Section 9.1.

---

## 11. Future Work

- **Re-split by prompt and retrain** — the highest-priority fix; everything else is secondary to a clean held-out evaluation
- Scale the corpus well beyond 55 questions, targeting 5,000+ pairs for a stronger DPO signal
- Rebalance the dataset to reduce the ~45% refusal share, so domain knowledge rather than declining dominates the learning signal
- Add reference-aware judging (give the judge access to the policy documents)
- Re-run both stages with W&B enabled to retain loss and KL traces
- Try ORPO or SimPO as DPO alternatives
